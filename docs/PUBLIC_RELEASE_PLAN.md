## 分发验收

源代码与生成运行产物分开；不将 bundle、node_modules 或个人资料加入源码 Git。优先选择可实际验证、无需现场构建的完整包。npm 来源可评估，但注册表权限和运行环境不可假设。官方允许的目标宿主安装方法须逐条验证，不把 Release ZIP 自动视为 marketplace URL。

只记录主动报送的采用与调用，不承诺完整自动监听；首次使用流程不未经请求改写用户的全局规则。公共目录版本不依赖被官方目录排除的生命周期 hooks。

## 完成边界

每批改动运行相关测试，发布候选运行完整回归和独立安装检查。对同一已验证批次不无依据重复。保存实际环境、失败原因和复现步骤。

开发者身份、准入、政策声明或不可访问的宿主验证不足时，完成可独立工作的部分并明确待办。正式上架须以门户实际通过为准；本地市场安装、源码注册及 skills.sh 分发均不等于官方上架。
