# 独立插件工具调用统计

## 0.4.1 来源分离

活动页默认统计宿主事件，可切换助手上报；两种来源不相加。历史无 source 字段的记录属于助手上报。API 主统计 `pluginCalls` 为宿主事件，手动上报位于 `pluginCalls.sources['assistant-report']`。同一准确调用 ID 可被宿主证据核实，保留原上报时间；不同 ID 不做猜测合并。范围与对账规则见 [DATA_ACCURACY.md](DATA_ACCURACY.md)。

`record_plugin_calls` 与 `record_skill_use` 使用独立文件和统计口径。前者存入持久数据目录的 `plugin-calls.json`，后者存入同目录的 `adoptions.json`。目录默认为 `$CODEX_HOME/skill-manager/data-v1`；未设置 CODEX_HOME 时为 `~/.codex/skill-manager/data-v1`，可由绝对路径 `CODEX_SKILL_MANAGER_DATA_DIR` 覆盖。旧 `.local` 仅作为显式迁移来源。两者不相加，也不互相转换。GitHub 等没有 Skill 的工具型插件可以直接进入调用排名。

首页保留“插件”和“Skill”两个按钮。默认插件视图统计插件工具调用；点击 Skill 显示“Skill 采用次数”，计数仍来自 Skill 采用账本。两栏均移除统计口径下拉框，仅保留年份与日期筛选。标题随按钮同步，日历、逐项热力图和排名使用对应账本。只有记录过的插件进入调用清单，不能用此清单判断哪些插件已安装。

## 自动采集（v0.3.3 起）

优先使用 [本机跨会话自动采集](AUTO_CAPTURE.md)。明确启用后从宿主 McpToolCall 完成事件记录真实调用，按原调用时间统计，无需助手额外上报。同一实际调用不要再用不同 ID 手动记录。仅覆盖本机可读日志；采集与 Skill 采用分开。历史 v0.3.2 分发包不含此功能。

## 手动接入规则

> 实际调用插件工具后，就近调用 `record_plugin_calls` 合批记录。每项包含 `id`、`plugin` 和 `tool`。`id` 使用该次调用的稳定 ID；不可取得时使用为该次调用生成并保留的 UUID。记录重试沿用 ID，新的实际调用（包括真实重试）使用新 ID。失败调用也计一次；尚未发出、仅发现工具、读取说明或计划中的调用不计。不传工具参数、结果正文或凭据，不跨日延迟，不回填历史。工具不可用时不伪造补记。

例如 GitHub 的命名空间是 `github`，完整工具名可为 `mcp__codex_apps__github_get_repo`。接口支持 `mcp__codex_apps__<plugin>_<tool>` 与 `mcp__<server>__<tool>` 命名；插件名须取已知工具的实际命名空间，不能从工具名的第一个下划线猜测。未支持的命名空间拒绝写入。

每批最多 32 项，同一调用 ID 跨批去重，同 ID 不同插件或工具拒绝整个批次。不同 ID 的同一工具调用分别计数。锁恢复复用已有的同机退出进程检查；未知锁仍保留。损坏账本拒绝覆盖，记录不成功时保留原文件。

## 边界与生效

- 下列限制适用于手动上报；自动采集边界见上方说明。手动上报是调用方主动记录的尝试数，不是成功次数。接口无法独立验证调用确实发生或插件归属声明；调用方须按实际工具清单填写。
- 日期按服务接收记录的时间和所选时区计算，不是宿主原始调用时间。没有记录的历史保持未知。
- 未启用自动采集时普通刷新与查询只读账本；启用后会增量接收宿主事件，但不解析聊天脚本。`functions.exec` 中的源代码可能含分支、循环、提前异常，不能仅凭文字作为已发生调用证据。
- 更新服务代码后需正常重载 MCP 服务，工具清单出现 `record_plugin_calls` 后才可开始记录。旧服务不会热更新。
- 本次没有把之前的 GitHub 操作补入 Skill 或插件账本。测试全部使用隔离临时目录。
