# v0.2.0 known limitations / 已知限制

- **Distribution / 分发**: prebuilt plugin ZIP → extract → `node install.mjs install`, with Node.js 20.18+ and compatible Codex CLI on PATH. The ZIP includes service, UI and both Skills. Source/MCP installation remains an alternative. No npm release, hosted marketplace or official directory listing; a ZIP download URL is not a marketplace URL.
- **Host UI / 宿主界面**: protocol/resource and browser checks exist; the latest complete native sidebar interaction and desktop language switching are not automated. Service startup does not prove every desktop version displays the entry. Do not modify hidden host settings to force it.
- **Platforms / 平台**: Windows with Node.js 20.18.1 and Codex CLI 0.163.0-alpha.11.2 is tested. macOS/Linux are unverified; archive execution is Windows-only.
- **Interface / 页面**: separate Activity, Manage and Setup views are implemented and browser-tested. Native desktop global entry, language-switch propagation, setup invocation in new/existing chats and desktop restart remain unverified because native UI control is unavailable in the test environment.
- **Evidence / 统计**: recording requires explicit caller participation; no automatic host-wide monitoring or complete historical backfill. Mentions/read requests are inferred signals. Missing coverage is unknown, not zero.
- **Installation / 安装**: keep the extracted package and Node executable in place. Use `install --replace-source` from the new extracted folder when upgrading; it explicitly changes the dedicated catalog registration. Do not install alongside a duplicate standalone MCP registration.
- **Data / 数据**: stop the service before migration or backup restoration. Migration backups are point-in-time, not continuous backups. Preserve files on corruption/conflicts and do not delete locks while a service may run.
- **Upgrades / 升级**: actual data written by the published v0.0.1-alpha.1 service was migrated to 0.1.0 with byte-identical backups and retained notes/counts. This does not cover every historical version or desktop UI behavior.
- **Windows startup / 启动**: one isolated snapshot-rollback service start closed unexpectedly; direct initialization and a fresh full lifecycle run passed. Its cause was not identified. Preserve diagnostics and original data on failure; do not delete data or disable security controls to retry.

Report issues via [GitHub Issues](https://github.com/zz11ss11zz/plugin-skill-manager/issues), including version, OS, Node/Codex versions and redacted errors. Do not upload private logs, credentials or indexes.

- **2026-10-26 marketplace reinstall**: with CLI 0.163.0-alpha.11.2, v0.1.1 installed and passed eight checks through uninstall, but relocated marketplace reinstall failed with Windows cache activation `os error 5`. Source/MCP standalone lifecycle passed all nine checks separately. Do not treat the earlier successful marketplace run as proof this intermittent issue is eliminated.

- **0.2.0 recovery**: the installer checks fresh install state before at most two retries of that specific Windows activation error. Clean 0.1.1 → 0.2.0 relocation, uninstall and reinstall passed through the packaged installer. This bounds recovery; it does not establish an OS-level fix or guarantee the error cannot recur.
- **Official submission / 官方提交**: local MCP submissions require approved-partner/organization allowlisting and verified identity. Those have not been established. Package metadata, review cases and supporting documents are prepared, but the project has not been submitted or approved. Native desktop walkthrough evidence remains outstanding.
