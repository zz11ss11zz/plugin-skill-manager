# 原生宿主执行表

## 环境与证据

目标是实际桌面宿主中的 MCP 侧栏。必须记录宿主产品名、版本、Windows 版本、Node/CLI 版本、候选 ZIP SHA256、安装方式、开始时间和测试执行者。Codex 的结果不自动证明 ChatGPT Desktop 的兼容性；拟发布到哪个宿主，就分别验证哪个宿主。

用独立 Windows 测试账户/干净测试配置，避免个人 Skill、聊天和记录进入视频。现有生产 MCP 是历史源码注册，不能当作此候选 ZIP 的干净安装证据。仅设置 CODEX_HOME 不一定隔离 `.agents/skills` 或整个桌面宿主；未核实宿主实际配置位置前不要开始写操作。

将 `fixtures/chart-demo` 复制至该测试账户实际用户 Skill 目录。通过清单确认来源为 user、路径属于测试账户。不要把 fixture 放进插件自身包中，否则它属于受保护的插件 Skill。不复制个人 auth/config，不导入生产聊天日志，不伪造历史活动。空记录也是有效测试状态。

使用宿主当前支持的本地插件安装入口安装候选；无入口则记 blocked，不能用单独注册旧源码服务替代。记录插件版本和来源，打开真正的原生侧栏，检查服务路径来自本次候选。现有安装分发可辅助 CLI 预检，但不等于门户审核包原生安装通过。

| H02 | 新聊天运行 setup；另在安装前已存在的聊天安装后运行 setup | 两种流程分别记录；只读检查接入，不自动改全局规则或写虚假事件 |

英文提示词的准确文本见 review-cases.json。每项实际记录 tool 名称、结果、文件/截图路径及视频时间码；`passed` 必须有可复核证据。失败记 failed，不能执行记 blocked，未开始记 not_run。使用 results-template.json 另存 results-实际日期.json，不改原始模板。

不能通过可用工具操控原生宿主或录屏时，保持未运行；由具备该宿主交互能力的操作者按此表执行。需要用户操作的是实际原生录制与无法自动完成的宿主步骤，不是要求重复批准已授权测试。
