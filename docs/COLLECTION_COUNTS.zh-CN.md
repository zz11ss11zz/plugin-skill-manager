# 关注技能库：计数与使用证据

## 能力、分发入口与机器上的安装

库页同时展示「对外提供的 Skill 数」和「发现的入口路径数」。固定仓库提交后，读取公开技能目录及插件清单声明的入口。按声明或文档区分正式分发、维护和归档；角色不明的入口单列待核对。归档和维护仍可展开查看，默认不计入对外能力数。

同一库内，已声明为同一 Skill 的打包副本归入一行，每个分发路径及所属插件都可展开。名称、入口指纹可作为匹配线索；单个 SKILL.md 相同只证明入口内容匹配，不能证明其脚本、依赖或安装来源相同。保留实现差异；无法确认对应关系时显示待核对，不强行去重。同名异源条目保留各自身份。能力分组只改变库页展示，机器上的安装实例、归档目标和账本 ID 均按原粒度保留。

## 逐项显示采用情况

先将已确认的安装实例与采用账本记录关联，再按所选时段查询。插件调用、文件读取和 Skill 采用分别计量。库级合计按原始采用事件去重：同一事件经三个打包路径展示仍只算一次，同一批次中确实记录的两次采用仍算两次。

| 查到的证据 | 界面显示 |
| --- | --- |
| 时段内有可归属的采用记录 | 展示已记录次数与最近一次时间；覆盖不完整时同时注明 |
| 已匹配安装，账本可读，但找不到该项记录 | 本账本未记录；最近采用时间留空 |
| 该项有历史记录，但所选时段没有 | 所选时段无采用记录 |
| 账本不可读、覆盖未知或安装归属不明确 | 标明未知及原因；不补零。可同时提示已查询账本中未发现记录 |
| 无匹配安装实例 | 显示未找到本机匹配；使用统计不适用 |

上述缺失状态不产生“从未使用”、闲置或清理建议。

## 验收样例

[baoyu-design 固定快照](https://github.com/zz11ss11zz/baoyu-design/tree/9c5253c002820d8dd4c9c31e9c8ca04b529a3e34) 有 22 个 SKILL.md 路径，顶层 skills/ 有 7 个正式入口。dataviz 的顶层入口及 baoyu-dataviz、baoyu-motion 两个插件内的入口具有相同 Git blob。顶层目录视图应有 7 行；展开 dataviz 能看到这三个分发位置。archive/ 和维护目录的条目另列。若另一个库新增仅随插件发布的独立 Skill，应纳入该库的正式条目，不能只扫顶层目录。

以已匹配的 claude-design、claude-dashboard、dataviz 和可读但没有三者记录的账本为样例，三行均应显示“本账本未记录”。再加入一条能匹配 dataviz 安装实例的采用事件，预期该行和全库合计各增加一次。断开账本后预期显示未知；放入同名但不同来源的实例后，不能将仅按名称命中的事件同时计给两个实例。
