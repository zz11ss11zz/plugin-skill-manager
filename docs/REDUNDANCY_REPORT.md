# 冗余候选报告（开发源码）

管理 → 清单／冗余候选 → 插件／技能。清单保留现有管理功能；切换视图保留插件／技能选择。候选报告不代表删除建议，也不升级已安装副本或已发布 v0.4.6 ZIP。

## 已实现

### 2026-11-02 v0.4.18 安装父项与互补原则（当前规则）

- 正式原则位于 [插件原则文件](../skills/skill-manager/references/redundancy-principles.md)，Skill 入口和项目 AGENTS.md 都指向它。署名（如 K-Dense Inc.）、来源集合（如 Scientific Agent Skills）、实际安装父项（如 academic-research-suite）不得混用；无法核实的集合或父项不猜测。
- 同一个实际安装单元内部（插件包或父 Skill 的全部子项）不建立相互冗余关系，包括兄弟组件；与外部安装单元仍比较其内部能力。作者和仓库不参与同安装单元判断。
- 入口描述中明确的“针对某项任务使用另一 Skill”路由是互补分工线索，不仅凭共同主题标签建立用途冗余关系。完全相同文档、同名不同内容仍走各自的跨安装单元比较。
- 本机已排除同 ARS 父项内编排/审稿组合，以及有明确设计检查/Python 实现分工的 scientific-visualization / matplotlib。没有据此删除或停用任何项目。

### 2026-11-02 v0.4.17 功能分组展示

- 组框左上显示实际命中的功能名称（如科研绘图、论文审稿、引用核验）；中间始终显示各项用途和来源，宽屏横排、窄屏堆叠。实际命中两项就显示两项，不为三栏示意填入额外 Skill。
- 出处以现有证据为限：用户目录、插件归属、父级套件、本地路径及入口 YAML 的文档署名。不把作者署名当作下载来源，不猜测 GitHub 仓库。
- 底部区分共同任务/目录比较证据与建议。对当前绘图、同套件编排/审稿和写作/文献摄入组合提供具体的分工判断；仍不把相近用途当作等价或删除授权。

### 2026-11-02 v0.4.16 修正（取代下方 v0.4.15 来源与闲置口径）

- 不再按 `openai-curated-remote` 市场整批排除：纳入已安装的第三方应用；保护 `openai-*` 插件身份、bundled/primary-runtime 来源及当前已识别的官方包。无法据此证明每个未来包的发布者身份，新增官方包需更新识别表。
- 闲置待评估：最近记录日早于一个日历月分界，或本机首次观察已超过一个日历月且无近期记录；分界当天的日粒度记录保守视为近期。无记录且观察不足一个月归入“记录不足”，账本失败不计为零。首次观察仅存于 `presence.json`，键为项目身份 SHA256，值为首次观察时间；不是安装时间，不证明连续覆盖。插件两种记录来源均参与最近使用判断，归属有歧义时不猜测。
- 用户 Skill 内部组件仅在报告请求时做有界扫描：识别有效 YAML name/description 的 SKILL.md 和 WORKFLOW.md，排除测试/示例/评测/产物/隐藏/链接目录。最多深度6、5000项、500个组件、8 MiB文本；单文件1 MiB。组件保留父项身份，不注册为新技能，不单独归档。插件包内不同技能仍不互判为重复安装；用户套件内部及跨套件可比较。
- 除描述词交并比外，报告使用封闭的中英文任务词汇表提取用途线索。共同任务不代表完整能力、输入输出或依赖一致；目录差异与用途说明必须同时呈现。父路由与其子工作流不因广泛描述互判用途重叠。实际语义相似度仍需人工核验。
- 页面分别显示纳入插件/Skill/组件数量和候选完整目录比对数量；“0个目录比对”不再被呈现为未扫描任何安装项。

- 2026-11-02 范围收紧：冗余报告仅纳入用户目录中的独立 Skill，以及已确认安装的非 OpenAI 插件家族（包含其旧版本缓存，以便核对版本）。系统 Skill、名称以 openai 开头的 Skill/插件、市场以 openai 开头的插件及未确认安装的缓存不进入候选或报告比较统计。该过滤仅作用于冗余报告，不改动总清单和活动账本。
- 同一插件身份和版本下的不同 Skill 属于同一插件包，不互作冗余候选；跨插件、跨版本及独立用户 Skill 仍可比较。描述比较先过滤来源与包内关系，再应用候选数量上限。
- 候选摘要直接展示技能名、插件名、版本与市场；独立 Skill 展示路径。超过三个不同名称的标题显示剩余数量，不再将来源相同的不同 Skill 渲染为无法辨别的重复行。

- 技能候选：相同 SKILL.md、同名不同文档、描述词语重叠。相交关系合并成组，分组依据明确对应实例，不表示整组两两相同。
- 目录比较：复用归档的文件快照，比较路径、类型与内容摘要；展示差异路径、每个实例的存在／缺失／未知状态。不同文档提供从首个不同的行开始的限长片段。不能完整读取时不报告目录一致。
- 证据：来源、插件版本和安装启用状态、目录文件数／字节数、实例级采用记录、文档中的工具名与文件引用。引用只作静态线索，不跟随读取、不执行脚本，不声称完整依赖图。
- 插件候选：按插件目录身份聚合同名来源／版本和多条安装记录；区分安装记录与仅缓存版本，展示关联 Skill 名称。不同插件中的相同文档不自动生成插件重复结论。未获得完整工具、依赖和独有能力清单，不建议据此卸载。
- 操作：个人 Skill 的保留标记复用已有本地备注与版本冲突保护。已标记保留项在候选视图禁用归档按钮。“本次暂缓”只保留在当前面板内，支持恢复显示；已核验内容变化会重新展示。
- 归档：复用预览、确认、取消及恢复机制；归档前重新校验目录快照。系统和插件内 Skill 不直接归档。归档移动目录并保留恢复能力，不等于释放磁盘空间。
- 插件状态读取失败时，报告仍返回本地比较，并明确标记安装状态未刷新；旧清单的普通查询失败语义保持不变。

## 长期无记录：尚不判定

入口提供 30／60／90 天观察窗口，但当前没有可信的连续监测区间及实例首次出现历史。报告明确显示覆盖待积累，不把记录首尾时间、账本 complete 标记或零记录当作“长期未用”的证据。

这部分需要后续实现连续观察历史及覆盖门禁。当前不生成长期无记录清理候选，也不从插件工具调用推断其所属 Skill 未被使用。采用读取失败显示不可用，不显示零。

## 扫描与展示边界

- 只有进入候选视图或刷新报告才请求目录比较，普通清单刷新不读取整个目录或活动账本。
- 复用 `check_plugin_status` 的可选参数 `includeReport: true`、`days: 30 | 60 | 90`，MCP 工具总数仍为 13。不读取新会话日志、不启动采集。
- 最多显示 50 个技能组、50 个插件组；每个技能组显示 20 个实例，整份报告最多比较 40 个技能目录。单目录沿用归档限制：10000 项、50 MiB，拒绝链接和特殊文件。
- 每组最多显示 100 条差异路径、50 条分组关系；文档片段每实例最多 25 行／4000 字符，不能替代完整原文。上限和不完整状态在界面显示。
- 功能重叠沿用描述词语检索的 500 个实例上限，不是语义相似概率。没有候选不代表没有重复。
