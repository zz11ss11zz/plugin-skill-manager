# v0.4.1 source update — 2026-10-28

Status: source changes on main and a locally deployed candidate. This update does not create a Release or replace v0.4.0 assets.

## Inventory layout and responsiveness

Plugins and Skills use the same heading/refresh toolbar, wrapping filter buttons, explanatory text and full-width search. English and Chinese share the implementation. Plugin totals count unique plugin IDs; Skill totals count files. Cache presence is not installation evidence.

Refreshing previously called `codex plugin list --json`, which can wait for marketplace discovery, then rescanned activity and rebuilt the page while controls were disabled. The refresh now calls the official app-server `plugin/installed` method, excludes uninstalled suggestions, and retains local and remote-origin installs. A failed or incomplete result preserves the previous list; it is not reported as zero. Navigation, category filtering and search remain available while the refresh button is disabled. Management requests skip activity-log collection and activity summaries; activity polling is suspended while Manage is open. Inventory-only results preserve existing activity charts.

The installed endpoint requires a Codex CLI that supports `plugin/installed`. Verified with Windows, Node.js 20.18.1 and Codex CLI 0.163.0-alpha.11.2. Older unsupported clients show a retryable error; no slow marketplace fallback is silently used. The endpoint returns localVersion where available and otherwise a reported remote version; these are not proof of what an already-running chat loaded.

## Activity evidence

- Host events are the default source; assistant reports have independent totals, calendars and rankings. Never add the sources to infer unique calls.
- Historical reports are preserved. Only an exact call ID/plugin/tool match can corroborate a report with a host event; the original report timestamp is retained.
- Skill adoption counts are assistant-reported. A file read or mention is not an independently verified Skill invocation.
- Capture state, scan freshness, recorded timestamp bounds and read issues are visible. Blank periods and zero pending bytes do not establish complete coverage.

API change: `pluginCalls.total` now represents host events. Use `pluginCalls.sources['assistant-report']` for reports. `check_plugin_status` returns `inventoryScope: 'management'` and omits activity fields; consumers must merge inventory fields or query activity separately. See [data definitions](../DATA_ACCURACY.md).

## Verification and limits

- Final full suite with `SKILL_MANAGER_TEST_CODEX=1`: 76 passed, zero failures/skips, including inventory-response preservation. See [VALIDATION.md](../VALIDATION.md).
- Packaged MCP inventory refresh measured 1,891 ms for 28 installed plugins and 67 Skill files; standalone file scan was about 100 ms. This is one local measurement, not a latency guarantee or native UI frame-rate measurement. The old market query did not finish during observation and was stopped; no fabricated speedup ratio is provided.
- Regressions cover pending refresh navigation, duplicate-request prevention, remote-origin installations, local-version priority, incomplete responses, management polling and the inventory-only protocol.
- Earlier v0.4.1 browser checks used synthetic fixtures in both languages, including source separation, daily selection and light/dark 360px layouts. They do not validate the subsequent inventory-layout changes in the native sidebar.
- Native sidebar rendering after service reload and reconciliation against official analytics remain unverified. No official-count or billing equivalence is claimed.

No activity ledgers, user logs, private configuration, local backups, installed bundles or historical submission drafts are included in this source update. Reload the MCP service after updating; an already-running process retains its previous bundle.
